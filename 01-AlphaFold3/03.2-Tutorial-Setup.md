# Assumptions and Expectations

This tutorial assumes that you:

* Have basic command-line experience (e.g., navigating directories, using bash, editing text files)
* Have a working CHTC account and can log into an Access Point (e.g., ap2001/2002.chtc.wisc.edu)
* Are familiar with HTCondor job submission, including writing simple `.sub` files and tracking job status with `condor_q`
* Have sufficient disk quota and file permissions in your CHTC `/home` and `/staging` directories

:::{hint} New to CHTC?
If you are new to running jobs on CHTC, complete the CHTC ["Roadmap to getting started
"](https://chtc.cs.wisc.edu/uw-research-computing/htc-roadmap/) and our ["Practice: Submit HTC Jobs using HTCondor"](https://chtc.cs.wisc.edu/uw-research-computing/htcondor-job-submission) guide before starting this tutorial.
:::

## Time Estimation
Estimated time: plan ~1–2 hours for the tutorial walkthrough. Each pipeline execution typically takes 30 minutes or more depending on sequence length and cluster load. Small test runs using `USE_SMALL_DB=1` often complete in 10–30 minutes.

# Clone the Tutorial Repository

1. Log into your CHTC account:
    
    ```bash
    ssh user.name@ap####.chtc.wisc.edu
    ```

2. To obtain a copy of the tutorial files, you can:

* Clone the repository:

  ```bash
  git clone https://github.com/dmora127/tutorial-CHTC-AF3.git
  cd tutorial-CHTC-AF3/
  ```

3. Create a directory in your `/staging/<netid>/` path titled `tutorial-CHTC-AF3`.

    ```bash
    mkdir /staging/<netid>/tutorial-CHTC-AF3/
    ```
  
4. Upload your AlphaFold3 Model Weights (`af3.bin.zst`) to `/staging/<netID>/tutorial-CHTC-AF3/`

    You should upload your AlphaFold3 model weights (`af3.bin.zst`) to this path. If you do not already have them, you will need to obtain them from the [DeepMind AlphaFold Team](https://github.com/google-deepmind/alphafold3/blob/main/docs/installation.md#obtaining-model-parameters). **You MUST have these weights before proceeding as they are required to run the inference pipeline of AlphaFold3.** Model weights can take several days to weeks to be approved. 

    :::{code}bash
    scp /path/to/af3.bin.zst ap####.chtc.wisc.edu:/staging/<netid>/tutorial-CHTC-AF3/
    :::

    :::{attention} Leave the Model Weights Compressed!
    Do NOT decompress the `af3.bin.zst` file. The AlphaFold3 pipeline on CHTC is designed to work with the compressed model weights directly.
    :::
    You can upload your `af3.bin.zst` using `scp`, `sftp`, `rsync` or another file transfer client, such as Cyberduck or WinSCP. For more information about uploading files to CHTC, visit our [Transfer Files between CHTC and your Computer](https://chtc.cs.wisc.edu/uw-research-computing/transfer-files-computer) guide. 

# About the Toy Dataset
A sample toy dataset has been included with this repository under `Toy_Dataset/input.csv`. You can use this CSV with the `scripts/generate_job_directories.py` helper script, as described in [Setting Up AlphaFold3 Input JSONs and Job Directories](#setting-up-alphafold3-input-jsons-and-job-directories). The toy dataset includes 4 jobs:

1) A simple single-protein job modeling the structure of the [_Sabethes Cyaneus_]() Piwi protein
2) A Protein-RNA job modeling the [_Aedes aegypti_]() Piwi protein complexed with a piwi-interacting RNA. 
3) A Protein-RNA-RNA job modeling the [_Aedes albopictus_]() Piwi protein complexed with a piwi-interacting RNA and a target RNA. 
4) A tetrameric complex of the [_Aedes aegypti_]() Actin protein. 

These examples help illustrate some of the potential use-cases of running AlphaFold3 on CHTC. 

# Directory Structure

The tutorial repository is organized to clearly separate **job logic**, **submission metadata**, **software definitions**, and **example data**, making it easy to understand, modify, and extend the workflow.

```
tutorial-CHTC-AF3/
.
├── AF3_Jobs
├── README.md
├── scripts
│   ├── data_pipeline.sh
│   ├── data_pipeline.sub
│   ├── generate-job-directories.py
│   ├── inference_pipeline.sh
│   ├── inference_pipeline.sub
├── software
│   ├── alphafold3-chtc.def
└── Toy_Dataset
    └── input.csv
```

:::{seealso} Understanding Your Directory Structure
:class: dropdown

**Top-level directories and files:**

* **`README.md`**

  The main entry point for the tutorial.
  It explains:

  * The purpose of the workflow
  * Required prerequisites (accounts, containers, data access)
  * How the pipeline is structured
  * Step-by-step instructions for running the data and inference stages
    Users should read this file before attempting to submit jobs.

* **`AF3_Jobs/`**

  This directory is created and populated during workflow execution.
  Each subdirectory corresponds to a single AlphaFold3 job instance and contains:

  * Job-specific input files
  * Generated AlphaFold3 JSON inputs
  * Output structures, logs, and metadata

* **`scripts/` — workflow logic and HTCondor submission files**

    This directory contains all executable logic and submission metadata for running AlphaFold3 at scale.

  * **`data_pipeline.sh`**
  A shell script responsible for the **data preparation stage** of the workflow.
  Typical responsibilities include:

    * Parsing input CSV or metadata
    * Generating AlphaFold3-compatible JSON inputs
    * Organizing per-job input files inside `AF3_Jobs/`
      This stage is CPU-focused and prepares everything needed for GPU inference.

  * **`data_pipeline.sub`**
    The HTCondor submit file for the data preparation stage.
    It defines:

    * Resource requests (CPU, memory, disk)
    * File staging behavior
    * Logging and error handling
      This file allows the data pipeline to be run as a scalable HTC workload.

  * **`generate-job-directories.py`**
    A helper Python script that:

    * Reads the input metadata (e.g., CSV)
    * Creates standardized per-job directory layouts
    * Ensures consistent naming and file placement across jobs
      This script is what enables clean, reproducible job fan-out.

  * **`inference_pipeline.sh`**
    The shell script that runs **AlphaFold3 inference** itself.
    It:

    * Consumes prepared job directories
    * Launches AlphaFold3 inside the container
    * Writes output structures and logs back into each job directory
      This script is GPU-focused and represents the most computationally intensive stage.

  * **`inference_pipeline.sub`**
    The HTCondor submit file for GPU-based inference jobs.
    It specifies:

    * GPU requirements
    * Memory and disk needs (including large reference databases)
    * Runtime constraints and retry behavior
      This file is tuned specifically for CHTC GPU resources.

* **`software/` — container and environment definitions**

  * **`alphafold3-chtc.def`**
    An Apptainer definition file used to build the AlphaFold3 container image.
    It captures:

    * The exact software environment
    * Dependencies and system libraries
    * Reproducible build instructions
      Including this file ensures transparency and long-term reproducibility of the tutorial.

* **`Toy_Dataset/` — example inputs**

  * **`Toy_Dataset/input.csv`**
    A small example dataset used for demonstration and testing.
    It allows users to:

    * Validate the workflow without large compute costs
    * Understand the expected input format
    * Safely experiment before scaling to real datasets

:::


Overall, this structure separates **conceptual stages (data vs. inference)**, **execution logic**, **submission metadata**, and **software definitions**, reflecting best practices for scalable, maintainable HTC workflows on HTC clusters.
