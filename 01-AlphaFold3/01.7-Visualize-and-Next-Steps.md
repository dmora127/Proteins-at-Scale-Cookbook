## Visualize Your AlphaFold3 Results

AlphaFold3 generates a variety of output files, including predicted 3D structures in mmCIF format (`<job_name>_model.cif`), ranking scores (`ranking_scores.csv`), per-seed and per-sample predictions, and confidence metrics (`<job_name>_summary_confidences.json` and `<job_name>_confidences.json`). These files are packaged into tarballs named `<job_name>.inference_pipeline.tar.gz` and returned to the Access Point. You will need to download these results from the Access Point to your local machine for visualization and further analysis.

1. Once your inference pipeline jobs have completed successfully, `exit` the Access Point SSH session and return to your local machine:

   ```bash
   [<netid>@ap2001 tutorial-CHTC-AF3]$ exit
   logout
   Shared connection to ap2001.chtc.wisc.edu closed.
   user@laptop ~ %
   ```

   Notice the change in the prompt, indicating you are back on your local machine.

2. For each job directory, download and extract the `<job_name>.inference_pipeline.tar.gz` file to your local machine. For the first toy-dataset job:

   ```bash
   scp <netid>@ap2001.chtc.wisc.edu:~/tutorial-CHTC-AF3/AF3_Jobs/Job1_XP_053696736.1_Sabethes_cyaneus/Job1_XP_053696736.1_Sabethes_cyaneus.inference_pipeline.tar.gz ./
   tar -xzvf Job1_XP_053696736.1_Sabethes_cyaneus.inference_pipeline.tar.gz
   ```

3. After extracting the tarball, you will find the predicted structures and associated metadata under `af_output/<job_name>/`. AlphaFold3 writes its outputs under a sanitized, lower-case version of the job name. You can visualize the predicted 3D structures using molecular visualization software such as PyMOL, ChimeraX, or VMD. To open the top-ranked model in PyMOL:

   ```bash
   pymol af_output/job1_xp_053696736.1_sabethes_cyaneus/job1_xp_053696736.1_sabethes_cyaneus_model.cif
   ```

## Next Steps

Now that you have successfully run the full AlphaFold3 two-stage workflow on CHTC GPUs, you are ready to extend this workflow to your own research projects, larger datasets, and more complex biomolecular systems. Below are recommended next steps to build on this tutorial.

### Apply the Workflow to Your Own Data

* Replace the tutorial sequences with your own proteins, RNA molecules, complexes, or mixed multimers.
* Use the CSV manifest and helper script to generate hundreds or thousands of AF3 job directories automatically.
* Experiment with multimeric protein assemblies, protein-RNA or protein-DNA complexes, and ligands or modified residues (e.g., 2′-O-methyl RNA, PTMs).
* Reuse the data pipeline outputs to run multiple inference configurations (different seeds, different AF3 options) without recomputing MSAs.

### Run Larger Analyses

Once you are comfortable with the basics, try:

* Large protein-RNA complexes (>10k tokens); see [Ultra-Large Complexes](#af3-ultra-large)
* Multi-seed inference strategies
* Modeling structural evolution by comparing AF3 predictions across species
* Integrating AF3 predictions into molecular dynamics or docking simulations, variant impact analyses, or evolutionary analyses
* Using AF3 for structural annotation of genomes, e.g., predicting full gene families with [DAGMan](https://chtc.cs.wisc.edu/uw-research-computing/dagman-workflows) workflows

### Get Help or Collaborate

* Reach out to [chtc@cs.wisc.edu](mailto:chtc@cs.wisc.edu) for one-on-one help with scaling your research.
* Attend office hours or training sessions. See the [CHTC Get Help page](https://chtc.cs.wisc.edu/uw-research-computing/get-help.html) for details.

## Data

AlphaFold3 jobs involve large and complex datasets, especially during the data pipeline stage. Understanding how data moves through the HTC system, and how to store it efficiently, is essential for scaling AF3 workloads.

Key AF3 data components include:

* **AF3 reference databases** (~750 GB unpacked in total), stored on selected CHTC execute points and accessed through the `(TARGET.HasAlphafold3 == true)` requirement, which avoids expensive per-job transfers of MGnify, UniRef, UniProt, PDB mmCIF, Rfam, RNAcentral, and the other databases.
* **Model weights** (user-supplied), typically about 2-4 GB depending on compression, stored in your `/staging` directory and transferred to GPU execute points through OSDF.
* **Data pipeline outputs**, one `.data_pipeline.tar.gz` per job, typically 100-300 MB depending on alignment depth.
* **Inference outputs**, one `.inference_pipeline.tar.gz` per job, including ranked mmCIF models, confidence metrics, and seeds.

For guides on how data movement works on the HTC system, see the [Data Staging and Transfer to Jobs](https://chtc.cs.wisc.edu/uw-research-computing/htc-job-file-transfer) guides.

This recipe uses the locally mounted AlphaFold3 databases by matching `data_pipeline.sub` jobs **only** to execute points advertising `HasAlphafold3 = true`, which lets many jobs *share* the databases and increases throughput. You can also match to execute points without the databases by removing the `&& (TARGET.HasAlphafold3 == true)` requirement; `data_pipeline.sh` then detects the missing mount and copies the databases through OSDF, which can add more than 45 minutes to a job. Reach out to the CHTC facilitators if you are considering this option.

## GPUs

AlphaFold3 inference is GPU-intensive, and selecting the right GPU resources is crucial for reliability and efficiency. CHTC provides a broad range of GPUs, from smaller RTX-series cards (8-16 GB) to large-memory accelerators such as A100s (40-80 GB) and beyond. Token count drives GPU memory needs; see [Key AF3 GPU Considerations](#af3-gpu-considerations) for the memory guidelines and the [GPU Guide on the CHTC Documentation Portal](https://chtc.cs.wisc.edu/uw-research-computing/gpu-jobs) for CHTC's GPU capacity.

## Glossary

| Term | Definition |
|------|------------|
| AF3 / AlphaFold3 | Diffusion-based deep learning system that predicts atomic-resolution structures for proteins, nucleic acids, and complexes. |
| MSA (Multiple Sequence Alignment) | Alignment of homologous sequences used to infer evolutionary relationships and structural constraints. |
| Template | Experimentally determined structure (e.g., from the PDB) used to guide modeling when available. |
| Fold input JSON / `fold_input.json` | AF3 input file containing sequences, chain IDs, and optional references to precomputed features. |
| Data pipeline | CPU stage that runs sequence searches (HMMER), collects templates, and generates MSA/template features for inference. |
| Inference pipeline | GPU stage that loads model weights and feature files to produce predicted structures and metrics. |
| Model weights | Trained parameters required by AF3 to perform inference (provided as `.bin` or `.bin.zst` files). |
| Tarball (`.tar.gz`) | Compressed archive used to package pipeline outputs for transfer back to the Access Point. |
| HTCondor submit file (`.sub`) | Job description file used by HTCondor to submit tasks to the HTC system. |
| Apptainer | Container runtime (formerly Singularity) commonly used on HPC/HTC systems to run reproducible environments. |
| Tokens | Unit of input size used by AF3; roughly 1.2 × residue count across chains is a common estimate. |
| Unified memory | Mode that allows AF3 to use system RAM in addition to GPU memory to accommodate very large jobs (slower than GPU-only execution). |
| OSDF | The Open Science Data Federation, a distributed data-delivery network used here to move containers and model weights into jobs. |
| JAX | Numerical computing library used by AF3 for model execution on CPU/GPU backends. |
