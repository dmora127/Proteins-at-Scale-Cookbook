Prepare the input files and job directories. The workflow is:

1. Create a CSV manifest of sequences (the toy dataset ships one: `Toy_Dataset/input.csv`).
2. Run `scripts/generate-job-directories.py` to create per-job folders under `AF3_Jobs/`, along with the two job-list files used by the submit files.
3. Confirm that each job directory contains `data_inputs/fold_input.json` and an empty `inference_inputs/` directory.

(af3-job-directories)=
## Setting Up AlphaFold3 Input JSONs and Job Directories

AlphaFold3 requires input JSON files that contain the query sequence(s) along with their metadata, such as chain IDs, sequence names, and molecule type. If you are using precomputed MSAs and templates, these JSON files also reference the paths to them. For this tutorial, you will create one JSON file per job. Each AlphaFold3 job has its own directory containing the input JSON file and any associated supporting files:

```bash
./AF3_Jobs/Job1_XP_053696736.1_Sabethes_cyaneus/
├── data_inputs/                       # inputs for the data pipeline
│   └── fold_input.json                # input JSON for the data pipeline
└── inference_inputs/                  # inputs for the GPU inference pipeline (filled by Step 1)
```

As your jobs progress through the two phases of the AlphaFold3 workflow, the output files are organized as follows:

```bash
./AF3_Jobs/Job1_XP_053696736.1_Sabethes_cyaneus/
├── data_inputs/
│   └── fold_input.json
├── inference_inputs/
│   └── Job1_XP_053696736.1_Sabethes_cyaneus.data_pipeline.tar.gz   # output of Step 1, input for Step 2
├── data_pipeline_<cluster>_<process>.err                           # stderr from the data pipeline job
├── data_pipeline_<cluster>_<process>.out                           # stdout from the data pipeline job
├── inference_pipeline_<cluster>_<process>.err                      # stderr from the inference job
├── inference_pipeline_<cluster>_<process>.out                      # stdout from the inference job
└── Job1_XP_053696736.1_Sabethes_cyaneus.inference_pipeline.tar.gz  # output of Step 2 (final results)
```

Each job directory holds the inputs and outputs for one AF3 run.

### AlphaFold3 Job JSON Input Format

An AlphaFold3 input JSON has this structure:

```{code} json
:filename: fold_input.json
:linenos:
{
  "name": "Job name goes here",
  "modelSeeds": [1, 2],
  "sequences": [
    {"protein": {"id": "A", "sequence": "..."}},
    {"rna": {"id": "B", "sequence": "..."}},
    {"dna": {"id": "C", "sequence": "..."}},
    {"ligand": {"id": "D", "ccdCodes": ["ATP"]}}
  ],
  "bondedAtomPairs": [],
  "userCCD": "",
  "dialect": "alphafold3",
  "version": 3
}
```

* `modelSeeds` requires at least one seed; each seed produces an independent prediction.
* `sequences` lists every molecule in the complex. A chain `id` can be a single ID or a list of IDs for identical copies (homomultimers).
* `bondedAtomPairs`, `userCCD`, and `userCCDPath` are optional (`userCCD` and `userCCDPath` are mutually exclusive).
* `dialect` and `version` are required. The helper script writes `version: 3`; the versions accepted depend on the AlphaFold3 release in your container.

Below is an example of a protein homodimer:

```{code} json
:filename: sample_fold_input.json
:linenos:
{
  "name": "2PV7",
  "sequences": [
    {
      "protein": {
        "id": ["A", "B"],
        "sequence": "GMRESYANENQFGFKTINSDIHKIVIVGGYGKLGGLFARYLRASGYPISILDREDWAVAESILANADVVIVSVPINLTLETIERLKPYLTENMLLADLTSVKREPLAKMLEVHTGAVLGLHPMFGADIASMAKQVVVRCDGRFPERYEWLLEQIQIWGAKIYQTNATEHDHNMTYIQALRHFSTFANGLHLSKQPINLANLLALSSPIYRLELAMIGRLFAQDAELYADIIMDKSENLAVIETLKQTYDEALTFFENNDRQGFIDAFHKVRDWFGDYSEQFLKESRQLLQQANDLKQG"
      }
    }
  ],
  "modelSeeds": [1],
  "dialect": "alphafold3",
  "version": 3
}
```

You can find more details about the AlphaFold3 input JSON format in the [AlphaFold3 GitHub repository](https://github.com/google-deepmind/alphafold3/blob/main/docs/input.md).

### Generate the Job Directories with the Helper Script

While you could create these folders and JSON files by hand, the repository includes a helper script, `scripts/generate-job-directories.py`, that reads a CSV manifest of sequences and (a) generates the job directories, (b) writes the `fold_input.json` for each job, and (c) writes the job-list files used by the submit files in Steps 1 and 2.

1. Run the helper script on the toy manifest:

   ```bash
   python3 ./scripts/generate-job-directories.py --manifest Toy_Dataset/input.csv --output_dir ./AF3_Jobs/
   ```

   For each row of the manifest it prints the job directory it created, the number of molecules, the estimated token count, and the estimated GPU memory:

   ```
   [+] Created Job1_XP_053696736.1_Sabethes_cyaneus with 1 molecules, 936 tokens, ~12.68 GB vRAM estimated.
   ...
   All multi-molecule AF3 job directories generated.

   The list of job directories has been written to: ./list_of_af3_jobs.txt
   The inference job list has been written to: ./list_of_af3_inference_jobs.txt
   ```

2. Verify that the job directories and input JSON files were created:

   ```bash
   tree AF3_Jobs/
   ```

   You should see one job directory per row of the manifest:

   ```
   AF3_Jobs/
   ├── Job1_XP_053696736.1_Sabethes_cyaneus
   │   ├── data_inputs
   │   │   └── fold_input.json
   │   └── inference_inputs
   ├── Job2_XP_001663870.2_Aedes_aegypti
   │   ├── data_inputs
   │   │   └── fold_input.json
   │   └── inference_inputs
   ├── Job3_XP_029709661.2_Aedes_albopictus
   │   ├── data_inputs
   │   │   └── fold_input.json
   │   └── inference_inputs
   ├── Job4_XP_001659963.1_Aedes_aegypti_Actin
   │   ├── data_inputs
   │   │   └── fold_input.json
   │   └── inference_inputs
   └── Job5_TesterJob
       ├── data_inputs
       │   └── fold_input.json
       └── inference_inputs
   ```

   The first four jobs are the examples described in [Tutorial Setup](./01.2-Tutorial-Setup.md); `Job5_TesterJob` is a tiny two-chain test case included in the manifest. Remove rows from the manifest, or lines from the job lists, to skip jobs.

3. View the manifest to understand its format:

   ```bash
   column -s, -t Toy_Dataset/input.csv | less -S
   ```

   Each row is one job: a `job_name` followed by one or more molecules, each described by a triplet of columns (`molN_type`, `molN_chain`, `molN_seq`).

The helper script accepts the following options:

| Option | Meaning |
|--------|---------|
| `--manifest <csv>` | Path to the manifest CSV (required) |
| `--output_dir <dir>` | Where to create the job directories (required) |
| `--jobs_list <file>` | Where to write the list of job directories (default `./list_of_af3_jobs.txt`) |
| `--inference_jobs_list <file>` | Where to write the inference job list with GPU memory estimates (default `./list_of_af3_inference_jobs.txt`) |
| `--seed <n> [<n> ...]` | Model seed(s) written to `modelSeeds` (default `1`); several seeds give several predictions per job |

:::{dropdown} Building Your Own Manifest File
A manifest is a CSV with a `job_name` column followed by one triplet of columns per molecule, `molN_type`, `molN_chain`, `molN_seq`, where `N` starts at 1:

```bash
job_name,mol1_type,mol1_chain,mol1_seq,mol2_type,mol2_chain,mol2_seq,...
```

For a single molecule:

```bash
job_name,mol1_type,mol1_chain,mol1_seq
ProteinA,protein,A,MKTAYIAKQRQIS
ProteinB,protein,A,GAVLILALLAVF
```

To model multiple molecules, add more `molN_*` column triplets. For example, a protein dimer and a protein-DNA complex:

```bash
job_name,mol1_type,mol1_chain,mol1_seq,mol2_type,mol2_chain,mol2_seq
ProteinA,protein,A,MKTAYIAKQRQIS,protein,B,MKTAYIAKQRQIS
ProteinB,protein,A,GAVLILALLAVF,dna,B,GCGTACGTAGCTAGC
```

To model homomultimers, give one molecule several chain IDs separated by a pipe character (`|`). For example, a trimer:

```bash
job_name,mol1_type,mol1_chain,mol1_seq
ProteinComplex,protein,A|B|C,MKTAYIAKQRQIS
```

**Adding ligands (SMILES or CCD codes).** In addition to `protein`, `rna`, and `dna`, the `molN_type` field accepts two ligand types; the ligand value goes in the `molN_seq` column.

* `smiles`: the ligand is given as a SMILES string. If the SMILES contains commas, wrap the field in double quotes so it stays a single CSV column:

  ```bash
  job_name,mol1_type,mol1_chain,mol1_seq,mol2_type,mol2_chain,mol2_seq
  ProteinLigand,protein,A,MKTAYIAKQRQIS,smiles,K,"CC(C1=CC=C(C=C1)O)(C2=CC=C(C=C2)O)CCC(NC)=O"
  ```

  produces `{"ligand": {"id": "K", "smiles": "CC(C1=CC=C(C=C1)O)(C2=CC=C(C=C2)O)CCC(NC)=O"}}`.

* `ccdCodes`: the ligand is given by one or more Chemical Component Dictionary codes, separated by `|` if there are several:

  ```bash
  job_name,mol1_type,mol1_chain,mol1_seq,mol2_type,mol2_chain,mol2_seq
  ProteinLigand,protein,A,MKTAYIAKQRQIS,ccdCodes,G|H|I,ATP
  ```

  produces `{"ligand": {"id": ["G", "H", "I"], "ccdCodes": ["ATP"]}}`.

As with sequences, a ligand can have multiple chain IDs separated by `|` in the `molN_chain` field.
:::

## Preparing Your List of (AlphaFold) Jobs

When working with HTCondor you will often hear the term "list of jobs": a file with one line per job that a submit file reads with the `queue ... from` syntax, so that one `condor_submit` creates many jobs. There are other ways to create many jobs directly in a submit file (for example `queue ... matching files`), but a separate list file is the most convenient when working with large numbers of jobs. For other approaches, see the CHTC guide [Submit Multiple Jobs Using HTCondor](https://chtc.cs.wisc.edu/uw-research-computing/multiple-jobs).

The helper script wrote two such files in the top level of the repository:

1. `list_of_af3_jobs.txt`, used by `data_pipeline.sub` in Step 1, lists one job directory per line:

   ```bash
   cat list_of_af3_jobs.txt
   ```

   ```
   Job1_XP_053696736.1_Sabethes_cyaneus
   Job2_XP_001663870.2_Aedes_aegypti
   Job3_XP_029709661.2_Aedes_albopictus
   Job4_XP_001659963.1_Aedes_aegypti_Actin
   Job5_TesterJob
   ```

2. `list_of_af3_inference_jobs.txt`, used by `inference_pipeline.sub` in Step 2, has the same job directories plus a second column with the recommended minimum GPU memory for that job, in GB:

   ```bash
   cat list_of_af3_inference_jobs.txt
   ```

   ```
   Job1_XP_053696736.1_Sabethes_cyaneus,13
   Job2_XP_001663870.2_Aedes_aegypti,13
   Job3_XP_029709661.2_Aedes_albopictus,13
   Job4_XP_001659963.1_Aedes_aegypti_Actin,24
   Job5_TesterJob,7
   ```

   The script estimates the GPU memory from the total token count across all chains (roughly `0.018 × tokens − 4.1` GB, with a floor of 7 GB) and warns when a job is estimated above 130 GB, which calls for the approach in [Ultra-Large Complexes](#af3-ultra-large). The values shown above are illustrative; your run prints the exact estimates.

:::{note}
Each line in these files corresponds to a single AlphaFold3 job that HTCondor will run. You can edit the files to add or remove jobs, or adjust the GPU memory column by hand, before submitting. Functionally, they are comma-separated values (CSV) files; you could add further columns to pass more variables to your jobs.
:::
