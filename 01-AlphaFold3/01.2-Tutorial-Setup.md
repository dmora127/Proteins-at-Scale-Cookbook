## Before You Begin

You will need the following **before moving forward** with the tutorial:

1. A CHTC HTC account. If you do not have one, request access at the [CHTC Account Request Page](https://chtc.cs.wisc.edu/uw-research-computing/form.html).
2. A CHTC `/staging` directory. If you do not have one, request it through the [CHTC large data guide](https://chtc.cs.wisc.edu/uw-research-computing/file-avail-largedata).
3. Basic familiarity with HTCondor job submission. If you are new to HTCondor, complete the CHTC [Roadmap to getting started](https://chtc.cs.wisc.edu/uw-research-computing/htc-roadmap) and read [Practice: Submit HTC Jobs using HTCondor](https://chtc.cs.wisc.edu/uw-research-computing/htcondor-job-submission).
4. AlphaFold3 model weights. Request the AF3 model weights from the [Google DeepMind AlphaFold team](https://github.com/google-deepmind/alphafold3/blob/main/docs/installation.md#obtaining-model-parameters).

:::{attention} Important: Request Your AlphaFold3 Model Weights Early!
Requesting AlphaFold3 model weights requires agreeing to Google DeepMind's terms of service. Ensure you comply with all licensing and usage restrictions when using AF3 for research. This tutorial does not distribute AF3 model weights. **Requesting the weights can take up to several weeks.** Ensure you have them before starting the tutorial.

Request the AF3 model weights from the [Google DeepMind AlphaFold team](https://github.com/google-deepmind/alphafold3/blob/main/docs/installation.md#obtaining-model-parameters).
:::

## Assumptions and Expectations

This tutorial assumes that you:

* Have basic command-line experience (e.g., navigating directories, using bash, editing text files)
* Have a working CHTC account and can log into an Access Point (e.g., `ap2001.chtc.wisc.edu` or `ap2002.chtc.wisc.edu`)
* Are familiar with HTCondor job submission, including writing simple `.sub` files and tracking job status with `condor_q`
* Have sufficient disk quota and file permissions in your CHTC `/home` and `/staging` directories

:::{note} Versions used in this tutorial
| Component | Value |
|-----------|-------|
| AlphaFold3 container | `osdf:///osg-public/containers/alphafold3-custom-v6.sif`, maintained by CHTC. An earlier build is also available locally at `/staging/groups/chtc_staff/containers/alphafold3.minimal.22Jan2025.sif`. |
| Input JSON format | dialect `alphafold3`, version 3 (written by the helper script) |
| Reference databases | Full AF3 default database set (~750 GB), pre-staged on CHTC execute points that advertise `HasAlphafold3 = true` |
| Model weights | Supplied by you as `af3.bin.zst` |

The container name encodes its build; when CHTC publishes a newer container, update the `container_image` line in both submit files.
:::

### Time Estimation

Estimated time: plan about 1-2 hours for the tutorial walkthrough. Each pipeline execution typically takes 30 minutes or more depending on sequence length, alignment depth, database location, and cluster load. Small test runs using `USE_SMALL_DB=1` often complete in 10-30 minutes.

The data-pipeline stage can be run with different CPU and worker settings. Single-core mode improves matchability and can increase overall throughput across many independent jobs, but each individual job takes substantially longer. For full-database jobs in single-core mode, expect runtimes of 1.5+ hours per query sequence, and potentially longer for conserved proteins with deep alignments.

## Clone the Tutorial Repository

1. Log into a CHTC Access Point:

   ```bash
   ssh <netid>@ap2001.chtc.wisc.edu
   ```

2. Clone the tutorial repository, which contains the executables, submit files, helper script, and toy dataset:

   ```bash
   git clone https://github.com/CHTC/tutorial-CHTC-AF3.git
   cd tutorial-CHTC-AF3/
   ```

3. Create a directory in your `/staging/<netid>/` path named `tutorial-CHTC-AF3`:

   ```bash
   mkdir -p /staging/<netid>/tutorial-CHTC-AF3/
   ```

4. Upload your AlphaFold3 model weights (`af3.bin.zst`) to `/staging/<netid>/tutorial-CHTC-AF3/`.

   If you do not already have them, you will need to obtain them from the [Google DeepMind AlphaFold team](https://github.com/google-deepmind/alphafold3/blob/main/docs/installation.md#obtaining-model-parameters). **You must have these weights before proceeding, as they are required to run the inference pipeline of AlphaFold3.** Model weights can take several days to weeks to be approved.

   ```bash
   scp /path/to/af3.bin.zst <netid>@ap2001.chtc.wisc.edu:/staging/<netid>/tutorial-CHTC-AF3/
   ```

   :::{attention} Leave the Model Weights Compressed!
   Do **not** decompress the `af3.bin.zst` file. The AlphaFold3 pipeline on CHTC is designed to work with the compressed model weights directly.
   :::

   You can upload your `af3.bin.zst` using `scp`, `sftp`, `rsync`, or another file transfer client such as Cyberduck or WinSCP. For more information about uploading files to CHTC, visit the [Transfer Files between CHTC and your Computer](https://chtc.cs.wisc.edu/uw-research-computing/transfer-files-computer) guide.

## About the Toy Dataset

A set of sample sequences is included with the repository under `Toy_Dataset/input.csv`. You can use this CSV "manifest" with the `scripts/generate-job-directories.py` helper script, as described in [Setting Up AlphaFold3 Input JSONs and Job Directories](#af3-job-directories). The toy dataset includes four jobs that illustrate different AlphaFold3 use cases:

1. Single protein: the [_Sabethes cyaneus_](https://en.wikipedia.org/wiki/Sabethes_cyaneus) Piwi protein
2. Protein-RNA: the [_Aedes aegypti_](https://en.wikipedia.org/wiki/Aedes_aegypti) Piwi protein complexed with a piwi-interacting RNA
3. Protein-RNA-RNA: the [_Aedes albopictus_](https://en.wikipedia.org/wiki/Aedes_albopictus) Piwi protein complexed with a piwi-interacting RNA and a target RNA
4. Protein complex: a tetrameric complex of the [_Aedes aegypti_](https://en.wikipedia.org/wiki/Aedes_aegypti) Actin protein

These examples help illustrate some of the potential use cases of running AlphaFold3 on CHTC.

## Directory Structure

The tutorial repository is organized to clearly separate **job logic**, **submission metadata**, and **example data**, making it easy to understand, modify, and extend the workflow.

```
tutorial-CHTC-AF3/
├── AF3_Jobs/                      # one subdirectory per job; populated by the helper script
├── README.md
├── data_pipeline.sub              # HTCondor submit file for Step 1 (CPU data pipeline)
├── inference_pipeline.sub         # HTCondor submit file for Step 2 (GPU inference)
├── scripts/
│   ├── data_pipeline.sh           # executable for Step 1
│   ├── inference_pipeline.sh      # executable for Step 2
│   ├── generate-job-directories.py
│   ├── cache_lookup.sh            # helpers used by the MSA cache (see Step 1)
│   └── cache_upload.sh
├── software/                      # empty; a place for a custom container definition if you build your own
└── Toy_Dataset/
    ├── input.csv                  # CSV manifest describing the four example jobs
    └── AF3_Jobs.zip               # pre-generated job directories for the toy dataset
```

:::{seealso} Understanding Your Directory Structure
:class: dropdown

**Top-level directories and files:**

* **`README.md`**: the main entry point of the repository. It mirrors this tutorial and should be read before submitting jobs.

* **`AF3_Jobs/`**: created and populated during workflow execution. Each subdirectory corresponds to a single AlphaFold3 job and contains the job's input JSON, the data-pipeline output tarball, logs, and the final inference tarball.

* **`data_pipeline.sub`**: the HTCondor submit file for the data preparation stage. It defines resource requests (CPU, memory, disk), file staging behavior, and logging, and targets execute points with pre-staged AF3 databases.

* **`inference_pipeline.sub`**: the HTCondor submit file for GPU-based inference jobs. It specifies GPU requirements (including per-job GPU memory), memory and disk needs, and runtime constraints tuned for CHTC GPU resources.

* **`scripts/`**: workflow logic.

  * **`data_pipeline.sh`**: runs the **data preparation stage** inside the container: it locates the AF3 databases, runs the sequence searches, and packages the resulting features into a tarball. This stage is CPU-focused.
  * **`inference_pipeline.sh`**: runs **AlphaFold3 inference** inside the container: it expands the feature tarball, prepares the model weights, runs the model on the GPU, and packages the predicted structures. This stage is GPU-focused.
  * **`generate-job-directories.py`**: reads the CSV manifest, creates standardized per-job directories and `fold_input.json` files, and writes the job-list files used by the submit files.
  * **`cache_lookup.sh`** and **`cache_upload.sh`**: helpers that `data_pipeline.sh` uses to look up and contribute alignments in the PATh alignment library when MSA caching is enabled.

* **`software/`**: a placeholder for a custom Apptainer definition file. The tutorial uses the CHTC-maintained container, so this directory is empty.

* **`Toy_Dataset/`**: example inputs. `input.csv` lets you validate the workflow without large compute costs and shows the expected manifest format; `AF3_Jobs.zip` holds pre-generated job directories for the same four jobs.
:::

Overall, this structure separates **conceptual stages (data vs. inference)**, **execution logic**, **submission metadata**, and **example data**, reflecting best practices for scalable, maintainable workflows on HTC systems.

## Software Environment

CHTC provides a shared Apptainer container for AlphaFold3, which is the `container_image` used by both submit files in this tutorial. Using it is recommended: it is tested against CHTC's pre-staged databases and GPU execute points, and it is cached by OSDF so jobs start quickly.

:::{dropdown} Building Your Own AlphaFold3 Apptainer Container (Advanced)
If you need a custom image (for example, a newer AlphaFold3 release), build a Docker image locally and convert it to an Apptainer image on the Access Point:

1. On your local machine, clone the AlphaFold3 repository:

   ```bash
   git clone https://github.com/google-deepmind/alphafold3.git
   cd alphafold3/
   ```

2. Build a Docker image using the provided `Dockerfile`:

   ```bash
   docker build -t alphafold3:latest ./docker/
   ```

3. Push the Docker image to a container registry (e.g., Docker Hub):

   ```bash
   docker tag alphafold3:latest <your-dockerhub-username>/alphafold3:latest
   docker push <your-dockerhub-username>/alphafold3:latest
   ```

4. On your CHTC Access Point, pull the Docker image and convert it to an Apptainer image, then move it to `/staging`:

   ```bash
   apptainer build alphafold3.sif docker://<your-dockerhub-username>/alphafold3:latest
   mv alphafold3.sif /staging/<netid>/tutorial-CHTC-AF3/
   ```

5. Point the `container_image` line in `data_pipeline.sub` and `inference_pipeline.sub` at your image, for example `osdf:///chtc/staging/<netid>/tutorial-CHTC-AF3/alphafold3.sif`.

For more on building containers at CHTC, see the [Apptainer Container Building Guide](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc).
:::
