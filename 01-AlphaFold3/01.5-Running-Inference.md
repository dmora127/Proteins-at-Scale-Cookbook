(af3-inference-pipeline)=
Once the data-pipeline jobs have finished generating alignments and features, the next stage is to run the AlphaFold3 inference pipeline on GPU-enabled execute points. This stage loads the model weights, expands the feature tarball from Step 1, and performs the diffusion-based structure prediction. Because inference is GPU-intensive, these jobs run on CHTC's GPU capacity and can be scaled across many GPUs in parallel. In the steps below, you will use a submit file that launches one inference job per sequence, each producing a final structure tarball ready for download and visualization.

This stage **does not** require the full AlphaFold3 databases, only the model weights and the feature tarballs produced in Step 1. As a result, you can run these jobs on a wider range of GPU execute points without worrying about database availability, including GPU execute points outside CHTC on the OSPool. To learn more about using additional capacity beyond CHTC, visit the guide [Scale Beyond Local HTC Capacity](https://chtc.cs.wisc.edu/uw-research-computing/scaling-htc).

## Review the Inference Pipeline Executable

1. Change to your `tutorial-CHTC-AF3/` directory:

   ```bash
   cd ~/tutorial-CHTC-AF3/
   ```

2. Review the inference pipeline executable script `scripts/inference_pipeline.sh`:

   ```bash
   cat scripts/inference_pipeline.sh
   ```

   For this tutorial, no changes are necessary. When you are ready to run your own jobs, review the overview below, as your AF3 jobs may require additional non-default options.

### Overview: AlphaFold3 Inference Pipeline Executable

This script implements the **structure inference portion** of the AlphaFold3 workflow. The inference pipeline loads model weights, runs the deep learning model on previously generated MSA/template features, and produces predicted 3D structures. It **does not** generate alignments or template features. This script is designed for execution inside HTCondor jobs and supports both containerized workflows and user-specified model weight files.

The script handles:

- Preparing a clean per-job working directory on the GPU execute point
- Expanding `.data_pipeline.tar.gz` results from the previous data pipeline stage
- Detecting and loading AlphaFold3 model parameters (**user supplied**)
- Running AlphaFold3 **inference only**
- Packaging predicted structures and metadata
- Cleaning up the job sandbox to minimize disk use

#### 1. Model Parameters and Containers

Unlike the data pipeline, the inference stage does **not need the full AlphaFold3 databases**. It only requires:

- A valid AlphaFold3 **model parameter file** (`.bin.zst`)
- A valid AlphaFold3 **container image**

The script allows you to specify a model file using:

```bash
--model_param_file <name_of_model_weights_file.zst>
```

If the model weights are compressed (`.zst`), the script automatically decompresses them into the working directory.

(af3-inference-options)=
#### 2. Command-Line Options

| Flag | Meaning |
|------|---------|
| `--work_dir_ext <name>` | Name appended to the working directory (`work.<name>`) |
| `--verbose` / `--silent` | Adjust verbosity |
| `--no_copy` | Do not copy the container or model parameters locally |
| `--container <image>` | Path to the Apptainer image |
| `--model_param_file <path>` | Path to the AlphaFold3 model weights |
| `--user_specified_alphafold_options "<options>"` | Additional arguments passed directly to `run_alphafold.py` |
| `--enable_unified_memory` | Enable unified GPU memory mode for large jobs |
| `--mem_preallocation_fraction <FLOAT>` | Set `XLA_CLIENT_MEM_FRACTION`: the fraction (or, with unified memory, the multiple) of GPU memory that JAX pre-allocates. Only applies with `--enable_unified_memory`; see [Ultra-Large Complexes](#af3-ultra-large). |

#### 3. Working Directory Setup

Creates:

```bash
work.<ext>/
    af_input/
    af_output/
    models/
    public_databases/
```

The inference stage expects the output from the data pipeline in the form of `*.data_pipeline.tar.gz` archives. These are extracted into `af_input/`, reconstructing the full feature directory structure required by AlphaFold3.

#### 4. Preparing Model Weights

Valid model weights may be provided in either uncompressed or `.zst` form. The script handles both:

- If compressed: `zstd --decompress > models/af3.bin`
- If uncompressed: `cp af3.bin models/`

#### 5. GPU Capability Handling

The script inspects the GPU compute capability using:

```bash
python -c "import jax; print(jax.local_devices(backend='gpu')[0].compute_capability)"
```

For GPUs with compute capability **7.x**, it automatically forces flash attention to `xla` and sets the XLA flags required to avoid runtime errors. You may also enable unified memory mode if working with especially large complexes.

#### 6. Running the AlphaFold3 Inference Stage

Inside the container, the script executes:

```bash
python run_alphafold.py --run_data_pipeline=false --run_inference=true --input_dir=/root/af_input --model_dir=/root/models --output_dir=/root/af_output
```

You may append custom AF3 flags through `--user_specified_alphafold_options "<options>"`. This allows advanced customization of the inference run, such as:

- Setting the model compilation bucket sizes (`--buckets 5132,5280,5342`)
- Altering or disabling JAX GPU memory pre-allocation (useful for larger complexes over 8k tokens; see [Ultra-Large Complexes](#af3-ultra-large))
- Other AlphaFold3-specific options

For the full list of AlphaFold3 options, refer to the [AlphaFold3 GitHub repository](https://github.com/google-deepmind/alphafold3/).

Output includes predicted 3D structures, ranking scores, and seed/sample-level predictions.

#### 7. Packaging Results

Each prediction directory under `af_output/` is archived as `inference_pipeline.tar.gz` and returned to the Access Point, where the submit file renames it to `<job>.inference_pipeline.tar.gz` in the job directory.

#### 8. Cleanup

After packaging the results, the script removes `work.<ext>/` and shell history files (`.bash_history`, `.lesshst`, etc.). This ensures minimal disk usage on execute nodes and prepares the job sandbox for automatic cleanup by HTCondor.

## Prepare Your Inference Pipeline Jobs

3. Open the submit file `inference_pipeline.sub` in the top level of the repository and set `MODEL_WEIGHTS_PATH` (line 9) to the location of your `af3.bin.zst` in `/staging`. You can pass additional options to the executable through the `arguments` attribute as needed; see the [command-line options](#af3-inference-options) above.

   ```{code} bash
   :filename: inference_pipeline.sub
   :linenos:
   :emphasize-lines: 9,18,32,40
   # CHTC maintained container for AlphaFold3
   # Can use the local CHTC copy at file:///staging/groups/chtc_staff/containers/alphafold3.minimal.22Jan2025.sif
   #          (use of file:/// needs to include "requirements = HasCHTCStaging == true" in the submit file)
   container_image = osdf:///osg-public/containers/alphafold3-custom-v6.sif

   executable = scripts/inference_pipeline.sh

   environment = "myjobdir=$(my_directory)"

   MODEL_WEIGHTS_PATH = /staging/<netid>/tutorial-CHTC-AF3/af3.bin.zst

   log = ./logs/inference_pipeline.log
   output = inference_pipeline_$(Cluster)_$(Process).out
   error  = inference_pipeline_$(Cluster)_$(Process).err

   initialdir = AF3_Jobs/$(my_directory)

   # transfer all files in the inference_inputs directory
   transfer_input_files = inference_inputs/, osdf:///chtc/$(MODEL_WEIGHTS_PATH)

   # transfer output files back to the submit node
   transfer_output_files = inference_pipeline.tar.gz
   transfer_output_remaps = "inference_pipeline.tar.gz=$(my_directory).inference_pipeline.tar.gz"

   should_transfer_files = YES
   when_to_transfer_output = ON_EXIT
   on_exit_hold = (ExitCode != 0)
   on_exit_hold_reason = "Non-zero Exit Code - Check Error and Output files."

   request_memory = 8GB
   # need space for the container (3GB) as well
   request_disk = 10GB
   request_cpus = 1
   request_gpus = 1

   # Use the CHTC recommended AF3 memory requirement based on the number of tokens
   gpus_minimum_memory = $(AF3_vRAM) GB

   # short jobs 4-6 hours so it is okay to use is_resumable
   +GPUJobLength = "short"
   +WantGPULab = true
   +is_resumable = true
   want_ospool = true

   +is_alphafold3 = true

   # Use --user-specified-alphafold-options to pass any extra options to AlphaFold3, such as
   # arguments = --model_param_file af3.bin.zst --work_dir_ext $(Cluster)_$(Process) --user-specified-alphafold-options "--buckets 5982"
   arguments = --model_param_file af3.bin.zst --work_dir_ext $(Cluster)_$(Process)

   queue my_directory,AF3_vRAM from list_of_af3_inference_jobs.txt
   ```

   :::{important} Point `MODEL_WEIGHTS_PATH` at your weights
   `MODEL_WEIGHTS_PATH` must be the path of the `af3.bin.zst` file you uploaded to `/staging` in [Tutorial Setup](./01.2-Tutorial-Setup.md). For example, if your NetID is `bbadger` and you uploaded the weights to `/staging/bbadger/tutorial-CHTC-AF3/af3.bin.zst`, set `MODEL_WEIGHTS_PATH = /staging/bbadger/tutorial-CHTC-AF3/af3.bin.zst`. The `transfer_input_files` line (line 18) turns this into an `osdf:///chtc/...` URL so that the weights can be transferred to GPU execute points both inside and outside CHTC.
   :::

   This submit file reads `list_of_af3_inference_jobs.txt`, which the helper script wrote next to `list_of_af3_jobs.txt` in [Data Wrangling](./01.3-Data-Wrangling.md). Each line has two columns: the job directory name, assigned to `$(my_directory)`, and the recommended GPU memory for that job in GB, assigned to `$(AF3_vRAM)`. The `gpus_minimum_memory` line (line 32) uses the second column so that each job requests a GPU with enough memory for its token count, and no more. This lets you programmatically submit _N_ jobs, where _N_ equals the number of AlphaFold3 job directories you created. Each job runs in its own job directory, uses the CHTC-maintained AlphaFold3 container image, and receives the model weights through OSDF.

   The inference jobs do not require the full AlphaFold3 databases, so there is no need to check for pre-staged databases on the execute points. The job is flagged as short (`+GPUJobLength = "short"`), eligible for the [CHTC GPU Lab](https://chtc.cs.wisc.edu/uw-research-computing/gpu-lab), resumable, and allowed to run on the OSPool (`want_ospool = true`), which maximizes the number of GPUs it can match. Jobs that exit with a non-zero code are placed on hold so you can inspect their `.out` and `.err` files.

### Choosing Appropriate GPU Resources

Beyond the model weights, your AlphaFold3 jobs may require different resource requests depending on the size and complexity of the molecules you are modeling. AlphaFold3 uses the concept of a "token" to represent the complexity of your input. **You can generally estimate the number of tokens as approximately 1.2x the sequence length.** For example, a protein with 1000 amino acids has roughly 1200 tokens. If you are modeling multimeric complexes, account for the combined sequence lengths of all chains. For structures that include nucleic acids (DNA/RNA), each nucleotide is one token. Post-translational modifications (PTMs) and additional ligands may also increase token counts, depending on the specific modifications involved.

Once you know the number of tokens, you can estimate how much GPU memory is needed. As a starting point, refer to the following general guidelines:

| Tokens     | Estimated GPU Memory Requirement |
|------------|----------------------------------|
| Up to 1200 | 8-10 GB                          |
| 1200-1850  | 15-20 GB                         |
| 2000-3000  | 35-40 GB                         |
| Over 3000  | 70+ GB                           |

The helper script fills the `AF3_vRAM` column of `list_of_af3_inference_jobs.txt` from this table. For your own jobs, edit that column (or set `gpus_minimum_memory` directly) to reflect the GPU memory your input needs.

:::{tip} Match the request to the need
CHTC has many smaller RTX-series GPUs (e.g., RTX 4000, RTX 5000) with 8-16 GB of GPU memory, and fewer large-memory cards (A100, H100). A job that needs 10 GB and requests `gpus_minimum_memory = 10 GB` stays eligible for the many small cards and starts sooner. Requesting 32 GB or more restricts the job to the large-memory cards, so only do so when the token table says you need it.
:::

For very large complexes exceeding 10k tokens, you may need to enable unified memory mode using the `--enable_unified_memory` flag in the executable arguments. This allows AlphaFold3 to use system RAM in addition to GPU memory, at the cost of **significantly slower performance**. See [Ultra-Large Complexes](#af3-ultra-large) for a worked example and the matching `request_memory` settings. We recommend reaching out to the CHTC Research Computing Facilitation team for assistance with very large complexes.

   ```bash
   condor_watch_q
   ```
